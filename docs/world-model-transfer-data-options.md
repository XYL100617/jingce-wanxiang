# 外部数据迁移评估（2026-10-29）

这些资料可以做算法预训练或跨域基线，但没有一份能单独证明万岁山 POI 预测准确。

| 来源 | 可用内容 | 授权/可得性 | 对万岁山的边界 |
|---|---|---|---|
| [Disney Theme Park Queue Dynamics（Hugging Face）](https://huggingface.co/datasets/matanzig/Disney-Theme-Park-Queue-Dynamics) | 页面列出约 3.46M 行、2018–2022 年、39 种设施描述、小时最大等待时间、运营、天气与日期字段；仓库标注 MIT | 仓库文件约 626 MB，清理 CSV 约 541 MB；数据卡称原始来源为 Kaggle，须保留来源链并自行核对上游条款 | 等待时间/运营动态可做外域基线；美国 Disney 的设施类型、运营方式、标签定义和万岁山节目型景点不一致，不能直接对齐 POI，也不能当作本地盲测 |
| [Theme-park visitor movement（Zenodo）](https://zenodo.org/records/20748587) | 23 名参与者、26 次主题乐园访问，含 GPS、POI 停留时刻、步行路径/热度与调查 | CC BY 4.0；数据包含同意参与者的去标识化轨迹，使用时需遵守许可和隐私说明 | 可做通用步行/停留/下一个 POI 行为先验；样本小、非代表性，没有排队人数/等待时间标签，不能校准万岁山拥挤度 |
| [Park Queue Times API](https://parkqueuetimes.com/developers) | 多园实时等待时间、营业状态、开放时间；历史到 2024 年 | 历史接口免费 Key 只可访问最近 48 小时；更长历史需付费计划，商业发布另有许可要求 | 可验证连接器与获取持续外域流；不覆盖万岁山，单园队列数据也不等于万岁山的演出散场/街区客流 |

仓库外已有的 `D:\jingxing\external-datasets\disneyRideTimes.csv` 先前外域实验中，线性/梯度提升模型在时间留出集都未胜过持久性；验证集选择的最佳融合权重为 0。该结果说明“数据量大”本身不等于迁移有效。

## 建议迁移方式

1. 用外域数据只学习可迁移的通用趋势或初始化先验，并单独报告外域时间切分结果。
2. 按景点类型/运营方式做部分池化；不可将设施名称直接映射为万岁山 POI。
3. 收到万岁山少量实测后，先做本地偏置校准，再与外域冻结模型、现场持久性、同日时段基线比较。
4. 最后按整日和活动场景留出本地数据；没有本地盲测通过前，外域模型继续只作为影子/先验，路线使用规则回退。
