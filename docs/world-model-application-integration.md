# 轻量化世界模型应用接入

## 当前接入

- `GET /api/v1/crowd-distribution` 调用已训练的 `synthetic-map1-crowd-trend-v0.1`，对地图1的 41 个 POI 输出 5、15、30、60 分钟的拥挤度比例和上升风险，并同时返回未经校准的模型密度估值。
- A 状态由 `application-crowd.js` 转换为模型输入。已知的 A 模拟 `QUEUE_SPIKE` 会作为模拟压力特征传入，并按同一模拟事件的已知 crowd 增量校正模型密度估值；未校正原始值仍保留供对比。训练数据和当前应用输入都标记为 T4 模拟数据；接口显式标记 `synthetic_transfer_inference`、`realtime:false`。
- 个性化规划通过 `livePlannerScenario()` 将应用场景预测和模型趋势风险接入 60 分钟内的 POI 预测。应用仿真器明确知道的队列突发等事件保留规则计算出的密度值，避免用跨模拟器的模型密度覆盖已知事件；模型原始密度值单独保留供对照。若已知模拟场景在预测期使密度增加至少 0.03，则趋势风险按该确定事件标为高风险；其他情况使用学习模型的概率。候选预筛按地图1示意坐标估算粗略到达时间，并读取该时刻的排队、拥挤度和趋势风险，避免只按当前排队截断低拥挤候选；这一步只做计算量较低的排序预筛。最终路线可达性、道路状态、预计到达时间和个性化效用分仍由统一地图1路网规划器复核。最终打分对拥挤度使用凸增惩罚，兼顾中等客流下的体验与高拥挤规避；游客问卷中的人流敏感度按 0–1 传入，并同步调节排队、拥挤和趋势风险代价。60 分钟以后的预测继续用规则回退。
- 世界模型只参与候选排序，不会放开关闭景点、封路、演出时间窗、步行上限或返程余量等硬约束。`PlanResult.itinerary` 会返回按实际预计到达时间插值得到的拥挤度、上升风险及预测来源；游客页面逐站显示模拟拥挤度和趋势风险，方案说明标为“模型模拟”。
- 当前 A 状态的排队字段是等待分钟数，不能当作训练集中的排队人数，因此适配器没有伪造 `queue_count`。道路通行时间基准在 A/B 模型中也不一致，因此没有把 A 的绝对道路时间冒充为训练特征。

## 人流展示和公告

- 应急页展示地图1景点当前模拟值及 15、30、60 分钟模型预测，每 15 秒随页面状态刷新。该刷新只代表本地演示状态刷新，不代表现场实时采集。
- 管理员可在较高模拟风险景点上选择“起草拥堵公告”。内容会写明需先核实现场；管理员提交后仍需审核通过，才会通过公开 `/api/operations` 返回给游客。
- 公告存储目前沿用本地演示文件，适合同一演示服务实例查看；Render 重启持久性和多实例共享能力尚未保证。公告也不会自动同步景区官方渠道。

## 节目参考和精度边界

- `server/data/program-schedule-reference.json` 含 11 个与地图1精确对应的节目/场地身份，可用于模拟场景。图片日期和有效期未知，记录为 `REFERENCE_ONLY`；模拟时段和容量是生成值，不可视为当日官方节目单。
- 训练/留出实验来自合成场景；此前留出合成场景中 crowd-ratio MAE 约 0.011–0.012，对照持久性基线约 0.021，但独立留出场景数量少。这个结果只说明模拟环境上的效果，不能推断真实景区准确率。
- 对当前应用模拟状态的单快照迁移检查显示，原始模型密度 MAE 在 5/15/30/60 分钟约为 0.0027/0.0060/0.0128/0.0250，持久性基线约为 0.0020/0.0060/0.0129/0.0250。模型迁移没有显示稳定提升，因此应用预测优先保留已知仿真事件的规则结果，并把模型风险作为额外排序信号；这不是现场精度证明。
- A 应用模拟器的迁移输入尚无独立校准集。现场人数、道路流量和节目散场传播规律仍需要真实采集或人工观测校准。没有这些数据之前，界面和公告文案都必须保留“模拟”标识。
