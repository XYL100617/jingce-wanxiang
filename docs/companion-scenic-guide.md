# 虚拟陪伴景区问答资料包

`server/data/companion/scenic-guide.json` 是给虚拟陪伴检索的景区资料包。景区背景统一为现实中的河南开封**万岁山·大宋武侠城**，以大宋文化和武侠江湖为主题语境。资料包另有 45 条由地图1当前项目图 `server/data/scenic_graph.json` 生成的节点条目，包含项目节点名、项目标签、统一 node ID、来源路径和可信状态。

地图1是在真实景区导览图基础上的项目化改绘。回答景区整体背景时，可以用有来源的背景条目；回答具体建筑、位置、道路、入口、设施或通行时，必须将地图1的改绘/示意数据与实地核验结果分开。改绘后的地图节点和标签不能自动升级成真实景区事实。更详细的来源边界见[地图来源核对记录](map-source-audit.md#项目背景与地图边界)。

45 条地图节点记录均为 `review_status: demo`、`source.kind: demo`、`source.verified: false`。另有一条来源指向项目范围和地图来源说明的背景与地图边界记录。地图条目只描述项目图里写了什么，不代表已核实的景区史实、实际建筑、服务设施、演出、开放状态或现场路网；项目问答结果会明确标示演示资料。

## 重新生成

在仓库根目录运行：

```powershell
node scripts/generate-companion-scenic-guide.js
```

服务启动时会加载该文件。它不是模型训练集。每次允许发起 GLM 问答时，系统提示都会携带万岁山·大宋武侠城的名称、开封位置、大宋/武侠主题及地图1“基于真实导览改绘、不是测绘图”的边界，并把选中角色的名称与关注角度写进同一系统提示；用户消息携带角色 ID 和少量匹配资料。小明侧重历史文化讲解，小红侧重美食市集，小李侧重观景摄影，小王侧重自然漫游，小五侧重有来源的主题串讲。GLM 会按角色写简短回答并选择资料 ID；服务器校验回答与证据的关联、演示标识和实时信息边界，再返回来源；不合格时使用本地回退。敏感、实时、应急和安全问题仍走本地规则与固定回退。

## 正式资料替换

要提供真实景区介绍和个性化推荐依据，应由景区确认名称、介绍、演出与设施信息，并记录来源链接/文件、审核人、审核时间和有效期。再将已确认条目按知识库契约写入相应 JSON 集合并标记审核状态。开放、排队、封路、天气和演出当日变更应接运营状态接口，不应写成静态事实。
