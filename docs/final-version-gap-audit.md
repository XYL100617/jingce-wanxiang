# 最终版功能与验证缺口盘点

核对日期：2026-10-29。本文依据最终版总体方案、ABC 最小闭环规范和当前仓库代码记录。页面可用、模拟测试通过与现场运营验证是不同验收层级。

## 已有可运行实现

| 模块 | 当前实现 | 验收边界 |
| --- | --- | --- |
| 图与状态 | 统一节点、道路、景点和演示状态；有状态与预测接口 | 当前道路与坐标不能代替现场测绘 |
| 规划与进度 | 多步规划、硬约束、演出时间窗、封路绕行、进度事件和滚动重规划 | 演示游客运行状态仍在服务进程共享，不可作为多游客生产运行时 |
| 地图 | 总览与逐段导航消费统一图和规划结果；带交互联调 | 地图是示意底图，缺少实测中心线、定位匹配和现场通行核验 |
| 路线DNA | 特点筛选、带特点投稿、统一规划器重算、游客点赞收藏、管理员审核 | 路线校验基于模拟图；热度来自应用内本地演示数据 |
| 个人中心 | 资料与授权、规划历史、景点/路线收藏、打卡、投稿、主页分享、数据导出和游客账号删除 | 打卡自报；规划运行状态仍共享；导出不包含审计日志和第三方模型处理记录 |
| 运营公告 | 管理者可创建待审核/已审核公告、设置有效期；当前事件从共享演示状态读取 | 公告只保存在本地 JSON；管理员审核不等于景区官方核实或正式发布 |
| 虚拟陪伴 | 有景区静态知识检索、GLM 提供方配置、按次路线/偏好授权与回退 | 自动到点讲解、系统推送未接入；实时运营资料仍是演示或缺失状态 |

## 尚未达到最终版生产验收的事项

1. **共享游客运行状态**：路线规划、当前位置和演示状态不是按服务端账号 ID 隔离，多个用户并发可能互相影响。
2. **持久化与部署**：账号、审计、社区和运营公告使用本地 JSON；会话与部分服务状态在进程内。尚无数据库、备份恢复、并发写控制和多实例验证。
3. **真实 SOS**：只有拨号链接和人工指引，未接入值班系统，也没有送达/接收回执。不能宣称已报警、已派救援或已确认安全通道。
4. **地图现场能力**：缺少经运营方确认或实测的道路中心线、可达入口、封闭规则、POI 坐标与定位匹配。地图路线只用于演示和交互验证。
5. **真实世界模型评估**：训练和评估数据以合成场景为主；当前结果只能支持模拟环境验证，不能宣称真实客流预测准确或模型已在现场胜过基线。
6. **运营人员角色**：当前权限有游客和管理者，未拆分值班调度、内容审核等细粒度运营角色，也未实现双人审核。
7. **陪伴持续服务**：到点自动讲解、主动休息提醒、后台应急推送尚未接入可靠定位、通知通道与运营事件订阅。
8. **页面交互验收**：本次环境未提供可用浏览器控制工具；自动化 HTTP 联调受本机回环权限限制，需在开发机浏览器继续走游客和管理者流程。

## 本轮新增

- 普通游客可导出账号资料、偏好、规划历史和个人中心数据；输入当前密码后可删除本人账号及社区记录，管理者账号不能从游客端自助删除。
- 管理者可以发布待审核公告，审核后按有效时间展示；公告与事件接口供应急页和陪伴查询读取。
- 运营公告以 `OPERATIONS_FILE` 指定的本地 JSON 文件保存。该实现增加了演示闭环，不构成景区官方运营系统接入。
- 统一页面色彩、字体层级、卡片、表单和交互态，增强移动端标签布局；未改地图渲染几何和道路图层。
