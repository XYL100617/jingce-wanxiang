# 数据治理规则

本文件固化负责人对**当前演示版本**的决策；`governance.json` 是机器可读对应物。两者都不被业务代码读取，本轮不改变运行行为。

## 1 当前图版本

`graph_version = 1.0`。该标识对应当前 45 node / 68 edge 的 DEMO 业务图，以及与该图直接绑定的记录。它独立于业务 JSON 中现有的 `schema_version`；本轮不向业务图增加字段，也暂不定义 1.0 之后的升级规则。无图绑定的公开网页及独立 mock 记录记 `N/A`。

## 2 当前运行模式

`operation_mode = DEMO`，`real_mode_enabled = false`。DEMO 可使用参考路网、示意估算距离、规则预测、T2 公开事实、T4 仿真数据及当前 POI 的 `node_id` 代理到达点；输出应称演示导航、模拟预测或仿真结果。当前不存在实际运行的 REAL 模式。未来 REAL 至少需要道路、入口、出口的运营确认或现场核验，且须完成安全审核、用途许可和版本签收。

## 3 园门规则

| 园门 ID | DEMO entry_allowed | DEMO exit_allowed | 证据 |
| --- | --- | --- | --- |
| `gate` | true | true | DEMO_RULE |
| `southgate` | true | true | DEMO_RULE |
| `westgate` | true | true | DEMO_RULE |
| `eastgate` | true | true | DEMO_RULE |

这四条是当前系统演示设定，**不代表真实园门已经现场核验或当天一定开放**。真实进出方向、时段和临时状态仍是 P0 缺口。

## 4 POI 到达点规则

在图版本 1.0 的 DEMO 中，现有 `poi.node_id` 暂作规划到达代理节点。它不是现场核验的真实游客入口。本轮不向 `scenic_graph.json` 或 Schema 加 `entrance_node_id`；未来取得真实入口资料后，再决定单入口或 `poi_entrances[]`，并单独签收。

## 5 数据来源策略

- T1 VERIFIED_OPERATOR：`CURRENTLY_UNAVAILABLE`。A 当前没有仓库之外的 GIS/CAD、真实道路、正式入口、排队、客流或运营数据库；本轮不假设隐藏 T1。
- T2 PUBLIC_VERIFIABLE：已核验 7 个独立网页、登记 24 条字段事实；有 URL 不等于有训练或再分发许可，且不等于当天运营安排。
- T3 VERIFIED_ON_SITE：`CURRENT_STAGE_NOT_PLANNED`。当前阶段不开展现场走查；未来条件允许时再讨论。
- T4 SYNTHETIC：当前规则、mock、预测可用于仿真和测试，必须保留 `synthetic=true`，不能作为真实观测。

## 6 道路准入

当前 68 条道路均为 `visual_only / REFERENCE_ONLY`，`verified_walkable = UNKNOWN`。它们可用于 DEMO 参考路线，不能作真实精确导航声明。未来 REAL 仅考虑 `operator_confirmed` 或 `verified_on_site` 的道路，同时核实入口、出口、方向、时效并完成安全审核。T2 公开地图线本身不能证明可走。

## 7 数据冲突规则

同一对象和字段出现不同公开值时，保留每条来源，不按发布时间自动覆盖；打印来源 ID 并标记 `CONFLICT_REVIEW_REQUIRED`，结合有效日期、发布主体、对象范围和业务语义人工复核。不同日期条件可能解释差异，不能据此抹掉旧行。

## 8 未知值规则

`UNKNOWN` 不得被校验器或录入流程自动替换为 `0`、`false`、`true`、默认时间或模拟值。没有排队观测不等于排队 0 分钟；没有道路状态不等于一定可通行；没有节目时间不等于永久停演。

## 9 数据变更规则

公开事实更新时新增来源记录、查询日期、原始快照或摘录及有效期；旧来源保留。现有 24 条 T2 来源登记关联采集者本地的 7 份最小文字摘录；因第三方网页许可/再分发权未明，摘录暂不纳入 Git，manifest 保留路径和 SHA-256。未保存完整网页原件、截图或授权副本。摘录只证明可见片段，不能证明页面当天未变化；详见 `source_snapshot_manifest.csv`。录入值须保持其 T2、T4、DEMO 和 REAL 使用边界；不得直接改业务 JSON 或训练数据。

## 公开资料复核策略

| 类别 | 例子 | 人工复核触发 | 使用边界 |
| --- | --- | --- | --- |
| A 静态资料 | 景区等级、正式名称、地址、景点名称 | 至少每月一次，或项目重大版本发布前再次核对；两者以先到者为准 | 记录原 URL、查看日期、页面日期和差异，旧记录保留 |
| B 半动态资料 | 整园营业时间、园门及设施开放说明 | 每次比赛演示前人工复核；跨日期使用时重新核对条件 | 不自动套用到单 POI、四门或真实导航 |
| C 高动态资料 | 当天节目单、临时停演、临时封路、特殊节假日时间 | 每次按具体使用日期人工查询当天运营公告或授权来源 | 没有当天来源保持 `UNKNOWN_DYNAMIC`；不得作为长期固定真值 |

执行流程：人工打开原 URL，核对发布主体、页面日期、适用日期和条件；只保存有权留存的最小片段并计算 SHA-256；更新来源登记与快照清单的实际复核日期、状态和差异。若页面不可访问或检索工具仅返回缓存，明确标记限制，不把摘录日期当成网页发布日期或当天运营确认。出现冲突时保留各来源，标记 `CONFLICT_REVIEW_REQUIRED` 并人工签收。当前不开发定时爬虫。

公开实体与内部 ID 候选见 `public_entity_mapping.csv`。名称相同仅构成候选，`REVIEW_REQUIRED` 不能进入真实入口、正式演出排期或 REAL 导航。
