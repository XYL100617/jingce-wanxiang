# 世界模型数据盘点与验证边界

## 当前盘点结论

截至 2026-10-29，仓库中没有发现可用于训练万岁山真实客流、排队、通行或游客满意度的本地训练集、训练脚本或模型权重。现有可运行输入主要是：

- `server/data/scenic_graph.json`：45 个节点、68 条边的统一示意路网；
- `server/data/current_state.json`：演示初始状态；
- `server/data/scenarios.json`：排队突增、道路关闭和减速等规则场景；
- `server/state/forecastSimulator.js`：可重复的规则预测器；
- `server/planner/`：基于图、状态、预测和硬约束的规划器；
- `server/examples/` 与 `docs/contracts/examples/`：契约和 HTTP 样例，不是实测训练集。

未发现字段齐全、带来源和许可信息的 `episodes`、游客轨迹、闸机客流或真实排队标签。地图坐标和内部道路仍以 `hand_map_reference`/示意数据为主；地图2的建筑和沿街设施为视觉模拟，不能用于证明现场导航精度。

## 当前可宣称的能力

系统当前提供 `EnvironmentForecast`、预测时间查询、规则重规划、事件回放和不确定性字段。`/api/snapshot`、`/api/world-model` 和导航接口均返回 `source_mode: synthetic_rule_simulation`、`trained: false`，规划器在模型不可用时使用规则回退。当前结论只能写为“规则模拟/模拟环境验证”，不能写成真实客流预测准确率、GNN/GRU 已训练或实时现场导航。

## 接入真实数据前的最小数据契约

每条训练或校准记录至少需要 `graph_version`、`scenario_id`、`source_tier`、`synthetic`、时间戳、可见环境状态、游客状态、合法动作、选定动作、下一状态、排队/通行标签、缺失掩码、随机种子和来源。真实数据需要同时记录授权范围、采样方法、单位、时区、覆盖日期和缺失说明。

训练/验证/测试应按整日、场景和图版本切分，不能把同一游客轨迹的相邻时间窗拆到不同集合，也不能把未来封路、未来排队真值或仿真内部潜状态泄漏到输入。真实、公开推断、人工核验和合成样本必须分层报告。

## 建议的可执行基线顺序

1. B0：静态兴趣路线与静态最短路。
2. B1：当前状态加规则重规划。
3. B2：环境预测加约束规划（当前仓库的主基线）。
4. 只有取得足够数据后，再比较 GRU/TCN、图编码器和动作条件转移。

评测至少报告 1/3/5 步排队与通行误差、到达时间误差、预测区间覆盖、总等待、无效步行、演出准时率、完成率、路线抖动、事件恢复时间和硬约束违规。模型版本、图版本或数据版本不匹配、观测过期、置信度低或推理超时时，必须回退到规则规划器。

## 仍需补充的资料

- 景区授权的道路中心线、POI 游客入口和通行规则；
- 不同营业日的分时段客流/排队/通行观测；
- 演出实际开场、散场和入场截止记录；
- 现场走查或人工采点形成的独立盲测路线；
- 数据许可、隐私授权、保留期限和删除流程。
